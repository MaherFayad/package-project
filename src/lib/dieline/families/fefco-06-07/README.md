# FEFCO group 06 + 07 — rigid-type (bliss) boxes and ready-glued cases / trays

Parametric dieline generators for every style that the **FEFCO Code, 11th edition** lists in group 06
(rigid-type boxes: two separate end pieces plus a body, stitched or glued) and group 07 (ready-glued
cases: one piece, shipped flat, set up in one move). They include the crash-lock / auto-erect bottom
and the pre-glued web corners. 33 models in all, each exported from `index.ts` as `DEFINITIONS`.

All sizes are **inner mm**. Board is corrugated (`E_FLUTE_KRAFT`, `E_FLUTE_WHITE`, `B_FLUTE_KRAFT`;
produce trays B/E kraft only). Bleed is 3 mm and the safe zone is 5 mm, the same as the corrugated
defaults in the core engine.

Every definition also carries a slug, an ar/en description, typical uses, a default size, 2 to 4

boxes and so on), validated limits (`params`, checked with zod), a `foldSequence` (ar/en steps whose
`stage` numbers match `DielinePanel.foldStage`), and `outerSize(dims, t)`, a closed-form outer size
for pricing and shipping.

## How the constructions are modelled

- **Group 06 bliss boxes.** The body is the main tree: the base is the root, tipped upright with
  `closedRotation = rotX(90°)`, so the wall above the base on the sheet becomes the front. Each end
  panel is a separate blank (`DielineBuilder.piece`) with its closed pose. The fold engine animates
  four stages: body walls up, then the ends move in, then the body flaps fold over the ends (0601,
  0602, 0606) or the end flaps fold inside the walls (0605, 0607, 0608, 0610, 0620), then the lid
  closes. Body flaps sit outside the ends, so in that case the body is L + 4t long (L + 2t otherwise).
- **0615 / 0616.** A four-panel tube with a joint, plus two end caps whose inner size is the tube's
  outer size plus clearance. The caps have single rims (0616) or rims rolled double at 180° (0615).
- **0621.** Two identical half shells. Each is a long wall with ½W flaps, plus an end wall folded
  W | v | W and a joint tab. Shell B is turned 180° about Y. Outer L = L + 2v, with v = clamp(4t, 8, 20).
- **Auto-erect (crash-lock) bottom** (`crashLockBottom`). Every bottom flap carries a 45° crease
  from its leading hinge corner (`extraCreases`). Fold stages follow the real erect sequence:
  stage 0 squares the tube, stage 1 folds the glued side flaps, stage 2 closes the long lock flaps
  with the front flap outermost. `AUTO_BOTTOM_SEQUENCE` is the matching ar/en step list. The bottom
  stacks 3 layers, so tube height = H + (3 + top layers)·t.
- **Web (gusset) corners** (`webCorner`). The corner square is split on its diagonal. Triangle A
  hinges 90° against the adjacent wall (its mesh pushed one board inward). Triangle B folds 180° onto
  A with pivotDepth 1.5, so the double web lies inside the wall and the outer size is unchanged.
- **No shared board.** Body flaps over the ends (0601, 0602, 0606) are mitred at 45° (taper = depth + 0.5 mm) so flaps of adjacent walls meet on the diagonal. 0605's end top flaps stop where the rim flanges start. 0608's tuck goes in behind the stitched end flaps (stack −2). 0621's joint tab pivots on its outer face so it lies behind the long wall. 0714's lid clears the base by t + 0.5 mm per side, room for the lid's own joint tab. A test checks every model, preset and limit corner (closed, and half folded) for parallel panels that share board volume.
- **Thickness compensation.** It follows the core engine: crease-to-crease = inner + layers × t.
  Tests check the folded model's `closedOuter` against `outerSize` at t = 1.5 and 3 mm, for the
  default size, every preset and every corner of the limits.

## Interpretations (FEFCO drawings give no dimensions)

The drawings were read from the FEFCO Code PDFs (sources below). These are the judgement calls:

- **0605:** the "v" body strips are modelled as rim flanges folded inward on an open top.
- **0621:** the W | v | W strip is read as a double end wall with a v spacer. Confidence is
  moderate, and it should be checked against a supplier sample.
- **0715 / 0717:** the integral partition flaps are modelled as separate slotted dividers in a
  2 × 3 grid. 0717's centre handle is two flaps that rise back to back with hand holes.
- **0716:** one perforation runs round the case: low across the front (display front, `tearFrontHeight`),
  high across the back, diagonal on the ends.
- **0747:** web corners at the back, and glue flaps at the front corners.
- **0752:** the die-cut cell tongues are modelled as cross partitions; the cell count comes from `tubeCells(L, W)`.
- **0759:** the lid has a front skirt that drops outside the front wall, plus side flaps.
- **0770–0774:** produce-tray variants. 0770 has stacking lugs, 0771 cut-down long walls with vents
  and hand holes, 0772 rolled double end walls with webs on the long walls, 0773 double long walls,
  and 0774 double long walls with hand holes.
- **Out of scope:** the codes that are new in the 12th edition (2022): 0702, 0704–0710, 0719–0730
  and 0740. The task specifies the 11th edition, and every 11th-edition code in groups 06 and 07 is
  covered. Most of the 12th-edition codes are crash-lock variants, so `autoBottomCase` with another
  `CaseTop` can add them.

## Integrator TODO

1. **StructureCode.** `src/types/structure.ts` `STRUCTURE_CODES` is a closed union, so the codes here
   are typed as `FamilyCode` strings. To register them, add the 33 codes to the union and to
   `GENERATORS` (`(d, t, f) => def.generate(d, t, f)`), `STRUCTURE_LIMITS` / `DEFAULT_DIMS` (`def.params`,
   `def.defaultDims`), `STRUCTURE_FAMILY` (`"CORRUGATED"`) and `FEATURE_SUPPORT` (all `NONE`) in
   `src/lib/dieline`. Then you can drop `build.ts`'s `generateFamilyDieline`, which mirrors the core
   `buildDieline`.
2. **Local types** (`types.ts`) that differ from the shared `StructureDef`:
   - `pieces` allows `3` (bliss box = body + two ends).
   - New fields: `subFamily`, `joint` (FEFCO M / A / M/A), `foldSequence`, `outerSize` and `generate`.
   - `uses` adds `"produce"` and `"industrial"`.
   - `features` is omitted, since no optional features apply; use `FEATURE_SUPPORT` `NONE`.
3. **Extra creases are not cuts.** `build.ts` removes `extraCreases` (web diagonals, glued-corner
   edges) from the cut lines. The core `buildDieline` only removes hinges, so it would draw a cut over
   each web-corner wall edge. Port that one-line change (`subtractSegments(e, [...hinges, ...extra, ...cutLines])`)
   when you move these generators into `GENERATORS`.
4. **i18n / seed / pricing.** Names and presets are in each definition; add `structures.<code>` keys,
   seed rows and rate cards as needed. `printAreaM2(model)` gives the printable area minus holes.
5. **Repo-wide `npx tsc --noEmit`.** It currently reports 9 errors, all in other owners' files
   (`src/components/designer/lib/catalog.ts`, `src/components/store/catalog.ts`,
   `src/lib/pricing/*`, `src/lib/dieline/__tests__/dieline.test.ts`). Those `Record<StructureCode, …>`
   maps are missing the 7 newer core codes. This folder adds no errors.

## Tests

`npx vitest run src/lib/dieline/families/fefco-06-07` runs 239 tests:

- **Catalogue:** the code list matches the 11th edition exactly; codes and slugs are unique; Arabic
  text has no diacritics; presets and defaults pass the limits.
- **Per model:**
  - no NaN anywhere;
  - closed outer = `outerSize` (2 thicknesses × all sizes and the corners of the limits);
  - flat at progress 0;
  - faces, bleed, safe zone and print-area arithmetic;
  - limit rejection (zod codes);
  - every `foldSequence` stage exists.
- **Construction:**
  - crash-lock stage order and 4 diagonal creases;
  - web-corner creases are never cuts;
  - bliss box is 3 blanks with W × H ends;
  - 0714 lid sits 3t over the base;
  - 0716 perforation;
  - 0770 lugs.
