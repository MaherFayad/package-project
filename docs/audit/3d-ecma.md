# 3D audit — ECMA tuck-end and ECMA specials families

Key: `3d-ecma` · Branch: `claude/exciting-albattani-8kzgsu-3d-ecma` · Scope: `src/lib/dieline/families/ecma-tuck`, `src/lib/dieline/families/ecma-specials` (+ tests). 34 models: 14 tuck-end / glued-end cartons and 20 specials (trays, sleeves, wallets, pillow, cone, polygonal, carriers, display, liquid).

## Method

| Step | Tool (`docs/audit/tools/3d-ecma/`) | What it gives |
|---|---|---|
| Test-pattern designs | `docs.ts` | A design doc per model as the designer creates it (default preset, default SBS board, print both sides): every outside face carries its name in the centre and a red **UP** at its top edge, every inside face `IN-<face>`. Variants: `finish` (soft-touch + gold foil on the names + spot UV / emboss on UP) and `features` (every option the model supports switched on). |
| Live designer renders | `capture.cjs` | Injects the doc as this browser's autosave and opens **`/en/design/<code>?resume=1`** (the real designer, `src/lib/library` → `DesignScene` → `PackagingScene`), Chromium + SwiftShader, 1440 × 900, 1x, reduced motion. Shots: iso, every face view (face picker → camera), back-bottom, 50 % fold, flat. `MOBILE=1`: 390 × 844 touch, rAF frame rate over 2 s. |
| Contact sheets | `sheet.cjs` | `docs/screenshots/audit/3d-ecma/*-before.jpg` / `*-after.jpg`. |
| Geometry numbers | `geometry.ts`, `faces.ts` | Closed outer vs inner, coplanar / interpenetrating boards (z-fighting), face parts. |
| Regression test | `src/lib/dieline/families/ecma-specials/__tests__/render-quality.test.ts` | Every model of both families × default + every preset × each SBS board (807 cases): no coplanar or interpenetrating boards closed; bleed covers every printable panel; each face part looks out, its artwork un-mirrored and upright on the walls. Fails on the original code for 10 models (z-fighting) and the cone (upside down). |

Reference for each style: the family READMEs (ECMA Code of Folding Carton Design Styles, 2009 rev.) and the 3D-visual baseline `docs/audit/3d-visual.md` (branch `…-audit-3d-visual`, sections 6 and 9: SP-01…07, TK-01…05, merged below).

Severity: **critical** broken flow / data; **high** clearly wrong to a packaging buyer or unprintable surface; **medium** noticeable realism defect; **low** nitpick.

## Findings — outside scope (shared engine / library / designer; not edited)

| ID | Sev | Where | Finding | Fix (precise) |
|---|---|---|---|---|
| O-01 | high | `src/lib/library/boxes.ts · baseStructure` | Pricing / production base comes from substring matching: `ECMA_TUCK_STE` and `ECMA_TUCK_AIRPLANE` (straight tuck) are priced as **ECMA_RTE** because the code contains "tuck"; hexagon, octagon, pillow and cone fall to `ECMA_STE`. | Use the family's own `def.baseCode` when present (`ecma-tuck` definitions carry it): `baseFor: (m) => BOARD_SPECS[m].family === "FOLDING_CARTON" && d.baseCode ? d.baseCode : baseStructure(…)`. |
| O-02 | medium | `src/lib/library/boxes.ts` (TUCK build) | Library builds ECMA tuck models without `model` options, so tuck lock (friction / slit), header height, leaflet allowance and lid height can never be set by a buyer; only the defaults render. | Add the options to `BoxModelDef.build(dims, { …, model })` and expose them in `ConfigPanel` from `ecmaTuckOptionsSchema`. |
| O-03 | medium | `src/lib/dieline/structures.ts · crashLockBottom` (used by GABLE_CARRY_CLB, BOTTLE_BASKET_4/6, core ECMA_CLB) | Both main-flap chamfers sit at the same end of the box (front at `u = L`, back at `u = 0` = box `x = L`), leaving one triangular opening in the bottom that shows the unprinted side flap; bottom artwork there is missing. | Mirror the back flap chamfer to `u = L0` (box `x = 0`), or use the tongue-on-roll-hinge construction from `ecma-tuck/closures.ts · crashLockBottom`. |
