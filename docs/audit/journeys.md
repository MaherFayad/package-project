# Journeys audit: the whole business, end to end (round 5)

**Key:** journeys · **Id prefix:** R5-JR- · **Base:** `4c11648` (rounds 1 to 4 merged) · **Date:** 2026-11-06 · **Branch:** `claude/exciting-albattani-8kzgsu-r5-journeys`

**Method.** `npm ci`, `prisma db push` + seed on a fresh SQLite DB (`ELBA_DATABASE_URL=file:./jr.db`), `next build` + `next start` with `OTP_DEV_ECHO=1 ALLOW_MOCK_PAYMENTS=1`. I walked five journeys as real people in Chromium (Playwright): first by hand-driven scripts with a screenshot at every step, then as specs under `e2e/journeys/`. Each journey runs in English on the desktop project (1280 px) and in Arabic on the phone project (360 × 780). The specs read their labels from the real dictionaries (an English label is looked up and its Arabic twin used), so a missing or wrong translation fails the Arabic run. At every money surface I compared the figure with the order row: price dialog, checkout summary, pay page, order page, admin order, receipt, vendor job and payouts. Screenshots: `docs/screenshots/audit/journeys/`.

**Business plan checks** (`docs/research-report.md`): managed model (§0), core flows (§4.1), prepaid with 3% discount (§7.3), 40/60 vendor payouts (§7.2), QC photos before dispatch (§7.4), reprint reserve (§6.2), KPI funnel (§6.3).

## 2. What works (verified in the browser, both languages)

- **J1 money is consistent end to end.** 500 gold-foil white mailers: price dialog EGP 26,120 + VAT 3,656.80 = 29,776.80 before the prepay discount; checkout, pay page, order page, admin and receipt all show subtotal EGP 25,351.70, VAT EGP 3,549.24 (14.000%), total EGP 28,900.94; the 3% discount (−768.30) applies to boxes, setup, die and foil, not delivery. Admin margin 4,351.43 = goods 24,841.70 − buy price 20,490.27; vendor advance 8,196.11 + balance 12,294.16 = 20,490.27.
- **State machine**: PENDING_PAYMENT → PAID → ACCEPTED → IN_PRODUCTION → QC_PENDING → SHIPPED → DELIVERED (mock courier), each with its WhatsApp message (ORDER_PLACED, PAYMENT_RECEIVED, VENDOR_NEW_JOB, STATUS_CHANGED, SHIPPED, DELIVERED); decline → reassign; dispute → reprint `ELB-…-R1` at EGP 0 to the buyer.
- **OTP**: wrong code → "The code is not right…"; after 5 wrong codes the code is dead ("Too many wrong attempts. Request a new code."); 10 failures per phone lock sign-in for 60 min (unit-tested; the 30 s resend cooldown is enforced in memory).
- **Payment failure**: card 4000…0002 → "Your card was declined… Nothing was charged.", a `FAILED` payment row and a PAYMENT_FAILED message; the retry pays once (one `PAID` row).
- **Expired price**: the pay page says "This price has expired. Start checkout again to get a new price." and offers no pay button.
- **Offline mid-design**: "You are offline. Your work is kept on this device."; back online it saves on its own; a refresh keeps the work.
